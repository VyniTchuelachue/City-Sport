# City Sport Cameroun

Website for the City Sport stores in Douala (Akwa, Kadji) and Yaoundé.
React and Tailwind CSS on the front, a small Node.js (Express) API behind it.

## Run it locally

Requires Node.js 20.19 or newer (22 recommended).

```bash
npm install
npm run dev
```

Open http://localhost:5173. The API runs on port 4000 and Vite proxies `/api` to it.

## Deploy to Vercel

1. Open https://vercel.com/new, sign in with the GitHub account that owns this
   repository, and choose **Import** next to `City-Sport`.
2. Leave every build setting as it is. `vercel.json` already tells Vercel how to install,
   build (`npm run build`), where the site is (`client/dist`) and that `/api/*` goes to
   the function in `api/index.js`.
3. Add the environment variables for the forms (next section), then **Deploy**.

Every push to `main` redeploys the site. Pull requests get their own preview address.

### Make the forms deliver on Vercel

Vercel functions cannot write files, so contact messages and availability requests need
somewhere to go. Set one or both in **Project > Settings > Environment Variables**:

| Variable | What it does |
| --- | --- |
| `RESEND_API_KEY` and `NOTIFY_EMAIL` | E-mails each submission through [Resend](https://resend.com). `NOTIFY_EMAIL` takes one address or several separated by commas |
| `NOTIFY_FROM` | Optional sender, for example `City Sport <site@citysportcmr.com>`. Needs a domain verified in Resend. Without it, Resend's shared sender is used, which only delivers to the address the Resend account was opened with |
| `FORMS_WEBHOOK_URL` | POSTs each submission as JSON to this address (Make, Zapier, Google Apps Script…), for example to forward it to WhatsApp or a spreadsheet |

Until one of them is set, the forms show "Ce formulaire est indisponible pour le moment.
Appelez directement le magasin." rather than confirming a message nobody would receive.
Redeploy after changing variables. The rest of the site works without any of them.

## Run it on your own server instead

```bash
npm run build
npm start
```

`npm start` listens on `PORT` (4000 by default) and serves both the site and the API from
one Node process. Here submissions are also kept in `server/data/messages.json` and
`server/data/requests.json`. The same variables as above add e-mail or webhook delivery;
put them in a `.env` file (see `.env.example`).

## What is in the site

| Page | Address | Notes |
| --- | --- | --- |
| Home | `/` | Hero, aisles, new arrivals, stores, brands |
| Shop | `/boutique` | Filters by aisle, gender, brand, reduced price; search; sorting. Filters live in the URL, so any view can be shared |
| Product | `/produit/:slug` | Size choice, add to "Ma sélection", stores that stock it |
| Stores | `/magasins` | Address, phone, hours, live open/closed status, map on request |
| About | `/a-propos` | SODICAM, sister stores, brands, payment methods |
| Contact | `/contact` | Message form, head office and store phone numbers |

The site is in French and English. French is the default; visitors with an English
browser get English, and the choice made with the switch in the top bar is remembered.

Open/closed status is always computed in Cameroon time (`Africa/Douala`), whatever the
visitor's own clock says.

**Ma sélection** is a shortlist, not a checkout. A visitor adds items, picks a store and
sends the list with a name and phone number; the store is expected to call back to confirm
availability. Nothing is reserved or paid online.

## Updating content

Everything editable is JSON in `server/data`:

- `stores.json`: addresses, phones, coordinates, photos and opening hours. `hours` has
  seven entries starting with Sunday, each `["09:00", "19:00"]` or `null` for a closed day.
- `brands.json`: the brand list and the one-line description shown on the About page.
- `products.json`: the catalogue. Each item has a `slug`, `brand`, `name` and `description`
  in both languages, `category` (`chaussures`, `vetements`, `accessoires`, `equipement`),
  `gender` (`homme`, `femme`, `enfant`, `mixte`), `price` in FCFA, optional `compareAt`
  (the crossed-out price), `sizes`, `image`, `isNew` and the `stores` that carry it.

On Vercel, commit the change and push: the site redeploys with the new content. On your
own server the files are re-read as soon as they change, with no restart.

Interface wording lives in `client/src/i18n/fr.js` and `en.js`. Head-office details,
payment methods and the sister-store list are in `client/src/lib/company.js`.

### The catalogue is a placeholder

The 30 products, their prices and their photos are demonstration data, generated by
`scripts/seed-products.mjs` (`npm run seed` rewrites `products.json` from it). Product
photos are loaded from Unsplash. Replace them with the real stock list and your own
photos before the site goes public: put images in `client/public/images/products/` and
point `image` at `/images/products/your-file.webp`.

## Forms

Both forms are validated on the server, carry a hidden honeypot field against bots, and
are limited to six submissions per ten minutes per visitor. On Vercel that limit is kept
per function instance, so treat it as a brake rather than a guarantee.

Delivery is handled in `server/lib/deliver.js`; the e-mail text is built in
`server/routes/forms.js`.

## Project layout

```
api/index.js            Vercel function: hands /api requests to the Express app
vercel.json             Vercel build, routing, security and cache headers
client/                 React app (Vite, Tailwind CSS v4)
  public/images/stores/ store photos
  src/components/       header, footer, product card, selection drawer…
  src/context/          language, stores, selection
  src/i18n/             French and English wording
  src/lib/              API client, price/time formatting, opening-hours logic
  src/pages/            one file per page
server/                 Express API
  app.js                builds the app (shared by Vercel and the Node server)
  index.js              Node server entry (npm run dev, npm start)
  data/                 JSON content, and stored submissions on your own server
  lib/                  data access, form delivery, rate limit
  routes/               catalogue, stores, forms
scripts/                catalogue seed
```
